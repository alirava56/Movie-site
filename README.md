# دیدمش!

دفتر شخصی فیلم و سریال برای مرور کاتالوگ، ثبت دیده‌ها و فهرست تماشا، امتیازدهی و یادداشت‌نویسی.

## اجرا

برای استفادهٔ مستقیم، `didamesh (3).html` را در Chrome یا Edge باز کنید. رابط، ثبت دستی، فهرست و پشتیبان‌گیری در حالت آفلاین در دسترس‌اند. کشف عناوین و نمایش پوسترهای آنلاین به اتصال اینترنت وابسته‌اند.

تغییر وضعیت، امتیاز، تاریخ یا یادداشت را در جزئیات هر عنوان با «ذخیره تغییرات» ثبت کنید.

برای استفاده از سرور محلی، با Node.js 22 یا جدیدتر `npm ci` و `npm start` را اجرا کنید و [دیدمش را در مرورگر باز کنید](http://127.0.0.1:4173/). سرور روی `127.0.0.1` گوش می‌دهد. فایل HTML ساخته‌شده همراه پروژه است.

پس از تغییر کد، خروجی HTML را دوباره بسازید. اگر سرور فعال است، آن را پس از ساخت دوباره اجرا کنید.

```powershell
npm ci
npm run build
npm test
npm start
```

## انتقال فهرست قبلی

1. فایل HTML جدید را در همان مسیر فایل قبلی و با همان پروفایل مرورگر باز کنید. دادهٔ معتبر `cine:items` به‌صورت خودکار وارد IndexedDB می‌شود.
2. برای جابه‌جایی میان فایل مستقیم، نشانی سرور، پروفایل یا مرورگر دیگر، از «پشتیبان» فایل JSON را دانلود کنید.
3. در مقصد، فایل را انتخاب کنید، پیش‌نمایش را بخوانید و ورود به فهرست را تأیید کنید. فایل نسخهٔ ۱، نسخهٔ ۲ و آرایهٔ قدیمی پذیرفته می‌شوند. موارد تکراری در گزارش ورود مشخص می‌شوند و رکورد موجود در فهرست اولویت دارد.

وقتی انتقال نیاز به بررسی دارد و دادهٔ اولیه در دسترس است، گزینهٔ «دانلود دادهٔ قدیمی» در پنجرهٔ پشتیبان ظاهر می‌شود. مرورگر دادهٔ هر نشانی را جداگانه نگه می‌دارد و رفتار حافظه برای فایل‌های `file:` به مرورگر وابسته است. [مستندات حافظهٔ مرورگر](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)

## معماری و قراردادها

| بخش | مسئولیت |
| --- | --- |
| `src/library.js` | اعتبارسنجی و یکسان‌سازی فیلدها، تشخیص هویت اثر، قوانین ادغام و کنترل تداخل ویرایش |
| `src/storage.js` | انتقال یک‌بارهٔ دادهٔ قدیمی و ذخیرهٔ تراکنشی IndexedDB با به‌روزرسانی میان زبانه‌ها |
| `src/catalog.js` | قرارداد کاتالوگ، صفحه‌بندی، تبدیل پاسخ سرویس به مدل نمایش و مسیر جایگزین جستجو |
| `src/main.jsx` و اجزای رابط | تجربهٔ فارسی و راست‌چین، جستجو و فیلتر، جزئیات، ثبت دستی و پشتیبان |
| `server/http.ts` و `server/catalog.ts` | سرور Fastify، سرو فایل و API کاتالوگ، کنترل مبدأ، کش و مدیریت خطا |
| `server/db` | اتصال PostgreSQL، طرح Drizzle، مهاجرت SQL و سیاست مالکیت ردیف‌ها |
| `server/library` | مسیرهای فهرست خصوصی، صفحه‌بندی، ثبت تکرارپذیر و ویرایش مشروط |
| `scripts/build.mjs` | ساخت HTML خودبسنده با React و فونت محلی، همراه سیاست امنیت محتوا و متن مجوزها |

`GET /api/catalog` پارامترهای `kind`، `catalog`، `genre`، `q` و `offset` را می‌پذیرد. پاسخ موفق `items`، `nextOffset` و `source` دارد. `nextOffset` باید برای درخواست بعد استفاده شود. در حالت جستجو مقدار آن `null` است. `GET /healthz` در دسترس بودن فرایند محلی را نشان می‌دهد.

سرور درخواست کاتالوگ را فقط به میزبان‌های تعریف‌شدهٔ Cinemeta و در صورت نیاز به سرویس پیشنهاد IMDb می‌فرستد. مسیر جستجوی فایل مستقیم از Cinemeta استفاده می‌کند. سال و امتیاز روی نتایج بارگیری‌شده فیلتر می‌شوند. بعضی نتایج جستجو امتیاز ندارند. [قرارداد کاتالوگ Stremio](https://stremio.github.io/stremio-addon-guide/sdk-guide/step2)

رابط فعلی از IndexedDB برای فهرست شخصی استفاده می‌کند. جستجوی کاتالوگ به منبع بیرونی درخواست می‌فرستد و پوسترهای دارای نشانی اینترنتی در مرورگر بارگیری می‌شوند. فهرست محلی تا ۳۰۰۰ عنوان و پشتیبان تا ۲۴ مگابایت را می‌پذیرد. آپلود محلی پوستر از JPG، PNG و WebP تا ۸ مگابایت و ۲۴ مگاپیکسل پشتیبانی می‌کند.

## راه‌اندازی پایگاه دادهٔ بک‌اند

نشانی PostgreSQL را در `DATABASE_URL` تنظیم کنید و `npm run db:migrate` را روی پایگاه دادهٔ موردنظر اجرا کنید. در محیط با نقش‌های جدا، `MIGRATION_DATABASE_URL` به نقش اجرای مهاجرت و `DATABASE_URL` به نقش اجرایی محدود اشاره می‌کند. نقش اجرایی به مجوز خواندن `accounts`، خواندن و افزودن در `catalog_titles`، و خواندن و نوشتن در `library_items` و `library_request_keys` نیاز دارد. نقش اجرایی را بدون `SUPERUSER` و `BYPASSRLS` ایجاد کنید تا سیاست مالکیت ردیف‌ها اعمال شود.

`GET /healthz` سلامت فرایند را نشان می‌دهد. `GET /readyz` اتصال PostgreSQL و حضور جدول‌های پایه را بررسی می‌کند. فهرست عمومی کاتالوگ مستقل از آماده بودن دیتابیس سرو می‌شود.

## اتصال سامانهٔ هویت به فهرست خصوصی

سازندهٔ سرور `createDidameshServer` گزینهٔ `resolveAccountId(request)` را می‌پذیرد. پیاده‌سازی سمت سرور باید پس از اعتبارسنجی هویت، شناسهٔ ثابت حساب متناظر با `accounts.id` را برگرداند. برای درخواست بدون هویت معتبر، مقدار `null` برگردانید. سامانهٔ هویت مسئول ثبت شناسهٔ ثابت در جدول `accounts` است. تا زمان اتصال اعتبارسنج، مسیرهای خصوصی با `401` پاسخ می‌دهند.

| مسیر | قرارداد |
| --- | --- |
| `GET /api/v1/library` | فیلترهای `status`، `kind`، `q`، `limit` و `cursor`. پاسخ `items` و `nextCursor` دارد. |
| `POST /api/v1/library` | افزودن دستی با `source: manual`، `title`، `kind` و `status`، یا افزودن از کاتالوگ با `source: catalog`، `imdbId`، `kind` و `status`. ثبت دستی نشانی پوستر HTTPS را هم می‌پذیرد. |
| `GET /api/v1/library/:id` | جزئیات عنوان متعلق به حساب، با `ETag` نسخهٔ فعلی. |
| `PATCH /api/v1/library/:id` | تغییر `status`، `watchedAt`، `myRating` و `note` با هدر `If-Match`. |
| `DELETE /api/v1/library/:id` | حذف عنوان متعلق به حساب با هدر `If-Match`. |

درخواست‌های تغییردهندهٔ فهرست به `Origin` هم‌مبدأ نیاز دارند. در صورت استفاده از پراکسی HTTPS، مبدأ عمومی را با `PUBLIC_ORIGIN` مشخص کنید. برای ثبت عنوان، از یک `Idempotency-Key` یکتا استفاده کنید. سرور کلید را به همان حساب و دادهٔ درخواست برای ۲۴ ساعت وابسته می‌کند. ویرایش و حذف با نسخهٔ قدیمی `412` می‌گیرند. خواندن یا تغییر شناسه‌ای متعلق به حساب دیگر پاسخ `404` دارد.

`npm test` آزمون‌های کاتالوگ، اجرای مهاجرت و جداسازی فهرست‌ها را با موتور PostgreSQL در PGlite اجرا می‌کند. اتصال پنل حساب و ورود پشتیبان قدیمی به حساب پس از اتصال سامانهٔ هویت انجام می‌شود.
